## B. Calendar page

Approved design (from the design canvas): **Concept A** (month grid + left filter rail) for **Week / Month**, **Concept B** (timeline with swimlanes by template) for **Quarter / Year**. One page, one shared filter rail, two renderers.

### B0 — Data (no new requests if possible)

- Reuse the cached queries the app already loads: `useEvents()`, `useTasks()` (all tasks), `useExpenses()`, `useTemplates()`, `useTemplateTaskCounts()`, `useMeetings()`, and `computeEventStats` for per-event numbers. The Calendar must not refetch what the Events page already has.
- Build `useCalendarData()` in `src/hooks/useCalendarData.ts` (memoized, pure helpers exported for testing):
  - per event: `{ event, template, color, start: eventDate, end: endDate, prepStart, stats }` where `prepStart` = **earliest task due date** of the event, falling back to `start − (template max daysBefore)` and then to `start`. Template max daysBefore comes from the existing template-task data (add a small service/hook only if none exists).
  - template counts are computed **before** the template filter is applied.
- Filtering, search and windowing are **client-side** — toggling a filter never triggers a request.
- Meetings for Week view come from the existing meetings data (`start`/`end` ISO UTC → local time).
- Volume note: this is fine at Caribbean Area scale. Leave a short comment where the window filter happens so it can later move to a server-side date filter (`new_eventdate`) if data grows.

### B1 — Window math + URL state

- **`src/utils/calendarWindow.ts`** (pure, strings in/out, extends `utils/dates.ts` helpers): `getWindow(view, anchor, custom?) → { start, end, days, columns, title }`, `shiftWindow(view, anchor, ±1)`, `dayIndex(date, windowStart)`, `overlaps(aStart, aEnd, bStart, bEnd)`.

  | View | Window | Columns |
  |---|---|---|
  | Week | Mon–Sun of anchor | 7 days |
  | Month | calendar month padded to whole Mon–Sun weeks (5–6 rows) | 7 days |
  | Quarter | calendar quarter, padded to whole weeks | ~13 weeks |
  | Year | Jan 1 – Dec 31 | 12 months |
  | Custom | `from` – `to` | weeks if ≤ 6 months, else months |

- **`useCalendarParams()`** with `useSearchParams` (works with the hash router): `view` (`week|month|quarter|year|custom`), `date`, `from`, `to`, `tpl` (comma ids; `none` = no template), `status` (default: all except Cancelled), `loc`, `overdue=1`, `mine=1`, `q`. Invalid values fall back to defaults. Reload, back button and shared links restore the same view.
- An event is "in the window" when `overlaps(start, end, window.start, window.end)` — or, in timeline views with prep windows on, when `overlaps(prepStart, end, …)`.
